## Further Findings & Identified Issues

I have performed an additional audit and discovered the following anti-patterns and bugs:

### 4. Side Navigation UI Alignment Bug (UI Issue) — **FIXED**
- **Location:** `src/shared/components/dashboard-link.component.tsx`
- **The Issue:** The `DashboardLink` component returned a wrapper `<div key={path}>` enclosing the `<a>` tag. This broke the Carbon Design System side navigation CSS structure (which expects `ul > li > a` or `nav > a`), resulting in disjointed alignment and padding for the "AIIMS Demographics" menu option.
- **The Fix:** Removed the `<div key={path}>` wrapper and moved the key to the `<a>` element. 

### 5. Duplicate "Record Data" Call-to-Action (Anti-Pattern) — **FIXED**
- **Location:** `src/demographics/demographics-dashboard.component.tsx` & `src/shared/components/dashboard-toolbar.component.tsx`
- **The Issue:** When a patient had no demographics recorded, the UI rendered two primary "Record Data" buttons: one in the `DashboardToolbar` and another identical primary action in the `EmptyState` component immediately below it.
- **The Fix:** Added a `hidePrimaryActionOnEmpty` prop to the toolbar component and passed it as `true` from the dashboard so only the EmptyState CTA renders when there is no data.

### 6. Unused SCSS Files (Dead Code) — **FIXED**
- **Locations:** `src/root.scss`, `src/demographics/demographics.scss`
- **The Issue:** Leftover SCSS files were not imported anywhere in the application.
- **The Fix:** Safely deleted both files.

### 7. Form Registry Hardcoding & Scalability (Architecture Anti-Pattern) — **FIXED**
- **Locations:** [index.ts](file:///c:/Met4l.DSCode/Projects/open-mrs/aiims-esm-demographics-app/src/index.ts)
- **The Issue:** Hardcoding single-spa lifecycle exports for each form required duplicate boilerplate for each of the 8 upcoming clinical forms.
- **The Fix:** Implemented `createFormExtensions(entry, loadDashboard)` factory in `src/index.ts` that automatically configures synchronization, async lifecycle wrappers, options, and routing metadata directly from `FORM_REGISTRY` entries.

---

### 8. Bundle Dependency Anti-Pattern (Bundle Optimization) — **FIXED**
- **Location:** [package.json](file:///c:/Met4l.DSCode/Projects/open-mrs/aiims-esm-demographics-app/package.json)
- **The Issue:** `@carbon/react` was declared under `dependencies` instead of solely in `peerDependencies` and `devDependencies`. In OpenMRS 3.x microfrontends, the host App Shell provides Carbon runtime modules via the import map; placing it in `dependencies` violates microfrontend architecture conventions.
- **The Fix:** Removed `@carbon/react` from `dependencies` and kept it in `peerDependencies` + `devDependencies`.

---

### 9. Duplicate Attribute & Age Parsing (DRY Anti-Pattern) — **FIXED**
- **Location:** [demographics.resource.ts](file:///c:/Met4l.DSCode/Projects/open-mrs/aiims-esm-demographics-app/src/demographics/demographics.resource.ts)
- **The Issue:** Phone attribute traversal (`patientObj?.person?.attributes?.find(...)`) and fallback age parsing were duplicated across both empty encounter and populated encounter paths.
- **The Fix:** Extracted `fallbackAge` and `fallbackPhone` once before branching, drastically simplifying data assembly.

---

### 10. Excessive Window Focus SWR Revalidations (Performance) — **FIXED**
- **Location:** [useFormEncounter.ts](file:///c:/Met4l.DSCode/Projects/open-mrs/aiims-esm-demographics-app/src/shared/hooks/useFormEncounter.ts)
- **The Issue:** `useSWR` relied on default window focus revalidation, triggering repeated background GET requests every time a clinician navigated back into the browser window or switched tabs.
- **The Fix:** Configured `{ revalidateOnFocus: false }` on the hook to eliminate wasteful network traffic.

---

### 11. Monolithic Observation Card Scaffolding (Architecture Anti-Pattern) — **FIXED**
- **Locations:** [observation-card.component.tsx](file:///c:/Met4l.DSCode/Projects/open-mrs/aiims-esm-demographics-app/src/shared/components/observation-card.component.tsx), `patient-card`, `husband-card`, `clinical-card`, `ses-card`
- **The Issue:** Every card duplicated identical Carbon `<Tile>`, header styling, icon wrappers, and field list mapping. Adding 8 new forms would result in massive code duplication.
- **The Fix:**
  - Created a reusable, configuration-driven [ObservationCard](file:///c:/Met4l.DSCode/Projects/open-mrs/aiims-esm-demographics-app/src/shared/components/observation-card.component.tsx) component.
  - Refactored `ClinicalCard`, `PatientCard`, `HusbandCard`, and `SesCard` to use `ObservationCard`, cutting component boilerplate by ~50%.
  - Added unit test suite [observation-card.component.test.tsx](file:///c:/Met4l.DSCode/Projects/open-mrs/aiims-esm-demographics-app/src/shared/components/observation-card.component.test.tsx) (7/7 tests passing).
